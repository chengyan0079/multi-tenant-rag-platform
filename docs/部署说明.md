# RAG-Ultra 部署说明

适用形态：**Docker 容器 / Linux 主机**。本文覆盖生产初始化、配置、启动与优雅关闭、Docker 部署。

## 0. 核心原则：启动只校验、不重建

生产环境下各启动项（Manager）**只校验依赖已就绪，不自动创建/重建基础设施**（Milvus 例外，见下）；缺失即记 `启动失败` 日志并退出进程（fail-fast）：

| 依赖 | 启动时行为 | 需预先准备 |
|---|---|---|
| PostgreSQL | 校验连通 + `rag_ultra` 库存在（不建表） | 建库 + 执行建表 SQL |
| Milvus | **启动时自动建库/建集合并加载**（缺失才创建，幂等） | 无需单独初始化 |
| MinIO | 校验桶存在且可达（不建桶） | 创建桶 |
| Redis | `ping` 探活 | 可达即可 |
| Nacos | 服务注册 + 配置预热 | 可达即可（`NACOS_ENABLED`） |

因此**上线前必须先完成第 1 节的一次性初始化**（Milvus 除外——服务启动会自动建库/建集合），否则服务起不来。

## 1. 一次性初始化（部署前执行）

### 1.1 PostgreSQL：建库 + 建表
建表基准在 `scripts/schema_postgresql.sql`（与 `store/orm_models` 一致）。库名需与 `config.POSTGRES_DATABASE` 对齐（默认 `rag_ultra`）。

```bash
# 建库（库名与 .env 的 POSTGRES_DATABASE 保持一致）
createdb -h127.0.0.1 -U postgres rag_ultra
# 建表
psql -h127.0.0.1 -U postgres -d rag_ultra -f scripts/schema_postgresql.sql
```

> 注意：PostgreSQL 库名统一为 `rag_ultra`（下划线）。`docker/docker-compose.yml` 的 `POSTGRES_DATABASE` 与 `config.POSTGRES_DATABASE` 默认均已对齐为 `rag_ultra`；若误用连字符 `rag-ultra` 建库，启动会报"数据库不存在"（仅差一个字符）。

### 1.1.1 API 调用日志表
`rag_api_call_log` 由 `scripts/schema_postgresql.sql` 建（本文件由 `scripts/gen_schema_pg.py` 依 ORM 生成）。
**PostgreSQL 启动项只校验不建表**，故新增/变更后须执行：
```bash
psql -h127.0.0.1 -U postgres -d rag_ultra -f scripts/schema_postgresql.sql
```
未建表时接口不受影响（日志仍打印，仅落库失败并告警）；中间件对每次调用落一行（请求侧 + 响应侧 + 耗时）。

### 1.2 Milvus：无需单独初始化
服务启动时由 `MilvusManager` 自动完成：确保 `config.MILVUS_DB_NAME`（默认 `rag_ultra`）数据库存在（缺失则创建）→ 创建集合 `config.MILVUS_COLLECTION`（默认 `rag_chunks`）与 dense/sparse 索引（缺失则创建）→ 加载到内存。已存在则直接加载，全程幂等。
> 向量维度取已加载的 BGE-M3 模型（`dense_dim`）。若更换向量模型/维度，须删除旧集合并重启服务重建、重新灌库（度量/维度在索引创建时固定，无法原地改）。

### 1.3 MinIO：建桶
应用文件桶需预先创建（与 Milvus 内部使用的桶相互独立）：
```bash
# 任选其一
mc alias set local http://localhost:9000 minioadmin minioadmin && mc mb local/rag-ultra
# 或在 MinIO 控制台 http://localhost:9001 手动创建
```
桶名与 `config.MINIO_BUCKET` 对齐（默认 `rag-ultra`）。

### 1.4 模型权重
把向量/重排/意图模型放到 `config.MODELS_DIR`（默认 `models/`）下，子目录见 `common/config.py`：`BGE_M3_DIR`、`BGE_RERANKER_DIR`、`BERT_INTENT_DIR`。缺失时对应能力降级（不阻断启动），但检索/问答质量受影响。

## 2. 配置（.env / 环境变量）

配置项定义见 `common/config.py`。常用项：

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOST` / `PORT` | `127.0.0.1` / `8800` | 容器内务必设 `HOST=0.0.0.0` |
| `WORKERS` | `1` | uvicorn 多进程 worker 数（>1 启用多进程） |
| `POSTGRES_HOST/PORT/USER/PASSWORD/DATABASE` | `localhost/5432/postgres/''/rag_ultra` | 元数据 |
| `REDIS_HOST/PORT/PASSWORD/DB` | `localhost/6379/''/0` | 缓存 / 会话 |
| `MILVUS_URI/DB_NAME/COLLECTION` | `http://localhost:19530` / `rag_ultra` / `rag_chunks` | 向量库 |
| `MINIO_ENABLED/ENDPOINT/BUCKET/ACCESS_KEY/SECRET_KEY` | `True` / `http://localhost:9000` / `rag-ultra` / `minioadmin` / `''` | 文件存储 |
| `NACOS_ENABLED/SERVER_ADDR/NAMESPACE` | `True` / `http://localhost:8848` / `public` | 服务发现 |
| `NACOS_CONFIG_*` | 见 config | 配置中心（提示词等） |
| `OPENAI_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL_NAME` | — | 生成用大模型 |
| `OPENAPI_ENABLED` | `False` | 是否暴露 /docs（生产建议关） |
| `MCP_API_ENABLED/TRANSPORT/HOST/PORT` | `True` / `streamable-http` / `127.0.0.1` / `8766` | 业务 API 的 MCP 服务（启动时把 API 封装为工具，供外部调用） |
| `MCP_API_ENABLED/TRANSPORT/HOST/PORT` | `True` / `streamable-http` / `127.0.0.1` / `8766` | 业务 API 的 MCP 服务（启动时把 API 封装为工具，供外部调用） |
| `MCP_API_EXCLUDE` | `/docs,/redoc,/openapi.json,/admin/health` | 不暴露为 MCP 工具的路径前缀 |
| `API_LOG_ENABLED/DB/MAX_BODY` | `True` / `True` / `8192` | API 调用日志：开关 / 是否落库 / 请求响应体记录上限（字节） |
| `API_LOG_EXCLUDE` | `/docs,/redoc,/openapi.json,/admin/health` | 不记录调用日志的路径前缀（探活等高频调用） |
| `IDENTITY_DEFAULT_ENABLED` | `True` | 未接网关时：缺身份头兜底为默认租户/用户；**接入网关后设 `False`**（缺头即拒） |
| `DEFAULT_TENANT_ID` / `DEFAULT_USER_ID` | `100` / `1001` | 兜底身份（仅自测用） |
| `AUTH_HMAC_ENABLED` | `False` | 调用方签名校验开关：接入网关后设 `True`（见 `core/auth`） |
| `AUTH_HMAC_SECRET` / `_PREV` | `''` | 当前 / 轮换期旧密钥；两者任一匹配即通过 |
| `AUTH_HMAC_TTL` | `60` | 时间戳允许偏差（秒），同时决定 nonce 去重窗口 |
| `AUTH_HMAC_EXCLUDE` | `/docs,/redoc,/openapi.json,/admin/health` | 不验签的路径前缀 |
| `LOG_LEVEL` | `INFO` | 统一日志等级（控制台/文件/uvicorn 共用）：DEBUG/INFO/WARNING/ERROR |
| `CORS_ALLOW_ORIGINS` | `[]` | 跨域白名单（JSON 数组或逗号分隔）；空=不放行任何跨域，`["*"]`=全部 |
| `CORS_ALLOW_METHODS` / `CORS_ALLOW_HEADERS` | `["*"]` | 允许的方法 / 请求头 |
| `CORS_ALLOW_CREDENTIALS` | `False` | 是否允许携带 Cookie/凭证 |

在中间件同一 compose 网络内运行时，`*_HOST` 用**服务名**（`postgres`/`redis`/`milvus`/`minio`）而非 `localhost`。

## 3. 启动运行

```bash
pip install -r requirements.txt
# 配置 .env 后
python run.py
```

- 多进程：`WORKERS=4 python run.py`（或 `.env` 设 `WORKERS=4`）。每个 worker 进程在 FastAPI lifespan 内**独立初始化自己的** PostgreSQL/Redis/Milvus/Nacos 连接，互不共享事件循环；Linux 下 `fork`、Windows 下 `spawn` 均兼容。
- 启动顺序见 README 的启动流程图；任一启动项失败会打印 `启动失败` 并退出，结合日志定位缺失的依赖。

### 优雅关闭
收到 `SIGINT/SIGTERM`（`Ctrl+C` / `docker stop` / K8s 终止）后：uvicorn 停止接收新连接 → 等待在途请求结束（`timeout_graceful_shutdown=30` 秒）→ 触发 lifespan **逆序释放**各 Manager（关 PostgreSQL/Redis/Milvus 连接、取消 Nacos 心跳并注销实例）→ 进程退出。

## 4. Docker 部署

### 4.1 中间件（已提供）
```bash
docker compose -f docker/docker-compose.yml up -d   # etcd/minio/milvus/redis/postgres/attu
```

### 4.2 应用镜像（示例 Dockerfile）
```dockerfile
FROM python:3.11-slim
WORKDIR /app
ENV PYTHONUNBUFFERED=1 HOST=0.0.0.0
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
# 模型权重建议以卷挂载，勿打进镜像：-v /path/models:/app/models
EXPOSE 8800
ENTRYPOINT ["python", "run.py"]
```

### 4.3 应用服务（compose 片段，加入同一网络）
```yaml
  rag-ultra:
    build: .
    environment:
      HOST: 0.0.0.0
      PORT: "8800"
      WORKERS: "2"
      POSTGRES_HOST: postgres
      REDIS_HOST: redis
      REDIS_PASSWORD: "1234"
      MILVUS_URI: http://milvus:19530
      MINIO_ENDPOINT: http://minio:9000
      OPENAI_API_KEY: "${OPENAI_API_KEY}"
    volumes:
      - ./models:/app/models      # 模型权重
      - ./logs:/app/logs          # 日志
    ports:
      - "8800:8800"
    depends_on:
      - postgres
      - redis
      - milvus
    restart: unless-stopped
```

> 上线顺序：先起中间件 → 完成第 1 节初始化（建表 / 建桶；Milvus 启动自动建）→ 再起 `rag-ultra`。

## 5. 常见问题

- **启动即失败 `PostgreSQL 数据库 'rag_ultra' 不存在`**：未建库，或库名与 `POSTGRES_DATABASE` 不一致（典型：下划线 `rag_ultra` 误建成连字符 `rag-ultra`）。执行 `schema_postgresql.sql` 或 `CREATE DATABASE rag_ultra`。
- **Milvus 启动失败 / 集合报错**：Milvus 不可达、库名不一致，或向量模型未加载（无法确定 `dense_dim`）。启动会自动建库/建集合，一般无需手动干预。
- **`FileProvider 健康检查未通过`**：MinIO 未建桶 / 不可达 / 账号不对。
- **FAQ/检索为空但服务正常**：模型权重缺失导致降级，或集合无数据（未建文档索引）。
- **Redis 连接失败**：compose 的 Redis 设了密码 `1234`，需在 `.env` 设 `REDIS_PASSWORD=1234`。
