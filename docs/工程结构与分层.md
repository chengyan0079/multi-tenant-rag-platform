# 工程结构与分层

RAG-Ultra 采用**分层 + 分包**组织：顶层按职责分层，层内按业务域分包。依赖方向严格自上而下（`app → core → store → common`），禁止反向依赖。

```
app/        接入层：HTTP 编排（不写业务/数据访问）
  api/      路由 + schemas（请求/响应契约）+ dao（按业务的数据访问，运营后台）
    user/       端用户接口（chat 会话等）
    dashboard/  运营后台接口；dao/ 为其数据访问层（FaqDao/FileDao/DocDao/HealthDao）
    schemas/    请求体(request)/响应(response)模型，集中契约
  managers/ 启动项（各 Manager，按 stage 并发启动）
  middleware.py / app_state.py / app_factory.py / server.py / main.py

core/       业务服务层：领域逻辑编排（不直接写 SQL / 不直连客户端）
  session/         会话（session_service + session_store[DAO] + models）
  session_memory/  会话记忆（memory_service + memory_store[DAO] + models）
  config_center/   配置中心（service + config_store[DAO] + nacos_config + query + prompts_*）
  qa_router/       问答编排（FAQ 优先 + 意图分流 + RAG）
  rag_retriever/   检索（Milvus 混合检索，经 store.milvus_store）
  rag_generator/   生成（LLM）
  rag_indexer/     文档解析 / 切片
  rag_model/       模型加载（embedding / rerank / llm client）
  intent/          意图分类
  file_provider/   对象存储抽象（MinIO / Mock）

store/      数据访问层（DAO / Repository）：唯一与 MySQL / Redis / Milvus / OSS 打交道的地方
  orm_models/      ORM 实体（按业务分文件：faq/file/knowledge/config/session + base）
  mysql_store.py   引擎 / 会话 / 探活（不建表，仅校验）
  redis_store.py   Redis（缓存 / 限流 / 聊天停止标记）
  redis_keys.py    Redis key 前缀与 TTL 集中管理
  milvus_store.py  Milvus 向量库（dense+sparse）
  faq_cache.py     FAQ 缓存（MySQL 源 + Redis）

common/     横切关注点：config / logger(含 trace_id) / response / exceptions
```

## 约定
- **数据访问只落在 `store/`**：基础设施存储（mysql/redis/milvus/faq）在 `store/`；业务域的数据访问以"业务包内 DAO"形态共存（`core/<域>/xxx_store.py`、`app/api/dashboard/dao/`），命名统一 `*_store` / `*_dao`。
- **`core/` 不写裸 SQL**：service 只做业务编排（校验 / 外部调用 / 状态机），持久化委托给本域 DAO（如 `config_center/service.py` → `config_store.py`）。
- **`app/` 只做 HTTP 编排**：路由验参（schemas）→ 调 DAO/Service → 组响应；不再内联 session/ORM。
- **Redis key/TTL 集中**在 `store/redis_keys.py`，各模块禁止硬编码 key。
- **schema.sql 由 ORM 生成**：`python scripts/gen_schema.py`（以 `store/orm_models` 为准）。

## 依赖方向
`app → core → store → common`（`core`/`app` 可依赖 `common` 与下层；`store` 仅依赖 `common`）。
说明：`app.app_state` 为进程级单例注册表，被 `core`/`store` 读取以获取运行期资源（redis/engine/milvus/model/file_provider），属共享内核，按需保留。
